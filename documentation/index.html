ML-GMS

M Lhuillier — GPS Monitoring System & Loans Management

PHP 8+ MySQL Tailwind CSS Chart.js PhpSpreadsheet

ML-GMS is a comprehensive, dual-database loan origination and servicing platform built for M Lhuillier. It manages the full lifecycle of loans—from origination through amortization scheduling, payment processing, and commission tracking—across six loan product types, with special support for GPS-monitored (GMS) collateral.

Purpose

This system tracks loans, auto-generates amortization schedules (primary & secondary ledgers), processes imported payment files via intelligent borrower/reference matching, allocates payments to ledger installments, and produces compliance reports (GMS commissions, receivables, collections).

Dual Database Design

The system connects to two MySQL databases simultaneously using a single Database class:

Connection KeyPurposeExample Tables
LOANTransactional loan dataloans, primary_ledger, secondary_ledger, payments, payment_allocations
MASTERReference/master dataregion_masterfile, loan_types, users
 
public function connect($db_type = 'LOAN')
{
    $host = $_ENV["{$db_type}_DB_HOST"];
    $db_name = $_ENV["{$db_type}_DB_NAME"];
    $username = $_ENV["{$db_type}_DB_USER"];
    $password = $_ENV["{$db_type}_DB_PASS"];

    $dsn = "mysql:host={$host};dbname={$db_name};charset=utf8mb4";
    $this->conn = new PDO($dsn, $username, $password, [
        PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION,
        PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
    ]);
    return $this->conn;
}

Manual Record Entry

The LoanService::saveManualRecord() method handles adding a single loan manually through the UI. The flow:

  1. Validate and sanitize input fields (principal, term, AOR, dates)
  2. Calculate monthly amortization: ceil((principal × ((AOR × 0.01) + 1)) / term)
  3. If GMS-tagged (date_installed present): compute dealer incentive (5% of principal), net proceeds, EY, EIR, secondary monthly
  4. Insert row into loans table
  5. Insert into car_loans or motor_loans if applicable
  6. Auto-generate primary ledger (all loans)
  7. Auto-generate secondary ledger (GMS loans only)

GMS Commission Logic

GMS = GPS Monitoring System

A loan is flagged as GMS when a date_installed is present (GPS device installation date). This triggers a secondary ledger and commission calculations.

  • Dealer Incentive: 5% of principal amount
  • Net Proceeds: Principal − Dealer Incentive
  • Secondary Monthly: (((net_proceeds × monthly_factor) × term) + net_proceeds) / term
  • EIR: Computed via Newton-Raphson IRR method on secondary cash flows

Amortization System

Primary Ledger

Every loan automatically gets a primary amortization schedule. The calculation uses the EY (Effective Yield) method:

// For each installment (1 to term):
interest = round(balance * (annualEY / 100) / 12, 2)
principal = round(monthly - interest, 2)
ending_balance = round(balance - principal, 2)

// On final installment:
principal = balance          // absorb any rounding
ending_balance = 0.00

Secondary Ledger (GMS Only)

Only generated for GMS-tagged loans. Uses net proceeds as the starting balance and secondary monthly for installment amounts. The interest rate is derived via EIR (internal rate of return) calculation.

EIR Calculation

The LoanService::getEIRRate() method implements the Newton-Raphson method to solve for the monthly interest rate where:

PV + Σ(PMT / (1+r)^t) = 0 for t = 1 to nper

private function getEIRRate($nper, $pmt, $pv, $guess = 0.01) {
    $rate = $guess;
    for ($i = 0; $i < 100; $i++) {
        $f = $pv;
        $df = 0;
        for ($t = 1; $t <= $nper; $t++) {
            $f += $pmt / pow(1 + $rate, $t);
            $df += -$t * $pmt / pow(1 + $rate, $t + 1);
        }
        $newRate = $rate - $f / $df;
        if (abs($newRate - $rate) < 1e-10) return $newRate;
        $rate = $newRate;
    }
    return $rate;
}

Payments

Import Flow

Payments are imported from Excel files and processed in a multi-step pipeline:

  1. File Upload: Excel file parsed, rows inserted into payments table with application_status = 'pending'
  2. Processing: PaymentService::processImportedPayment() is called per payment
  3. Matching: Payment is matched to a loan via reference number or borrower name
  4. Allocation: Payment amount distributed across open ledger installments
  5. Status Update: Payment marked as fully_applied, partially_applied, or unmatched

Auto-Matching Algorithm

The PaymentService::matchLoan() method uses a two-tier matching strategy:

PriorityMatch FieldLogic
1Reference NumberExact match on loans.reference_number. If exactly 1 result found, use it. If >1, skip.
2Borrower NameNormalized full name match across all loans. Falls back when reference is empty/ambiguous.

Ledger Allocation

Once matched, the allocatable amount (principal + interest) is distributed to open primary ledger rows in installment order:

// Get open primary ledger rows (status IN unpaid, partial)
// Sort by installment_no ASC
foreach open_row:
    apply = min(remaining, row.remaining_due)
    row.amount_paid += apply
    row.remaining_due -= apply
    remaining -= apply
    if row.remaining_due == 0: row.status = 'paid'
    else: row.status = 'partial'
    // Also mirror to secondary ledger if GMS loan

Payment components (VAT, penalty, interest_diff) are recorded as non-ledger allocations. Any excess beyond the total remaining due is stored as an excess allocation.

Reports

GMS Commissions Report

Located at public/gms_commission.php. Lists all GMS-tagged loans (those with gps_provider = 'GMS' in car_loans or motor_loans) along with their dealer incentive amounts. Supports date-range filtering and export.

Running Receivables Report

Located at public/running_receivable_report.php. Shows outstanding balances across all active loans. Tracks what is owed vs. what has been paid, organized by loan type. Key columns: borrower, reference number, total due, total paid, balance remaining.

Collection Report

Located at public/collection_report.php. Summarizes payment collections by period (daily/weekly/monthly). Groups collected amounts by loan type and payment method, providing a reconciliation view against expected collections.

Authentication

  • Login: public/login.php validates credentials against the MASTER database users table
  • Sessions: User identity stored in $_SESSION with prefixed keys (admin_name / user_name)
  • Force Password Change: New users with flag force_password_change = true are trapped in the change password modal (Escape key disabled, modal forced open)
  • Logout: Destroys session and redirects to login
